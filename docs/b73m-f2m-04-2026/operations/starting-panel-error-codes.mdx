When a sequence step on the [Starting Panel](/manuals/b73m-f2m-04-2026/operations/starting-panel) fails, the panel sets the state to **ERROR** and publishes the step index together with the error code, so the state line reads for example `ERROR 10/18 — code 208`. Both numbers are recorded before retrying.

The codes below are the `codeOnError` values of the configured sequence steps, so each identifies the exact step that failed. Steps marked as warnings do not abort the sequence: the panel continues, but the reported state may not match the installation.

FTD.aero Support: **+48 519 737 800** (telephone or WhatsApp).

| `106` | Projector 1 did not respond to shutdown. | Projector 1 is off. | Check whether projector 1 is turned off. If not, turn it off with the remote control. Report the issue to the technical team or FTD.aero Support to check the network and power connection. |

## Computer wake-up and readiness codes

| Code | Description | Expected | Action |
|---|---|---|---|
| `215` | Avionics PC did not respond to Wake-on-LAN. | Avionics PC is on and boots up. | Check whether the Avionics PC is turned on. If not, turn it on with the power button. Report the issue to the technical team or FTD.aero Support to check the network and power connection. |
| `216` | IOS PC did not respond to Wake-on-LAN. | IOS PC is on and boots up. | Check whether the IOS PC is turned on. If not, turn it on with the power button. Report the issue to the technical team or FTD.aero Support to check the network and power connection. |
| `217` | Display PC did not respond to Wake-on-LAN. | Display PC is on and boots up. | Check whether the Display PC is turned on. If not, turn it on with the power button. Report the issue to the technical team or FTD.aero Support to check the network and power connection. |
| `218` | Timeout while waiting for PCs to start after Wake-on-LAN. | All PCs are on, booted and reachable on the network. | Check whether all PCs (Avionics, IOS, Display) are turned on and have finished booting. If any PC is still off or stuck, turn it on with the power button or restart it. Report the issue to the technical team or FTD.aero Support. |
| `220` | Timeout while waiting for CLS to start. | CLS is running and reports ready status. | Check whether the CLS computer is turned on. Check that all emergency stop buttons are released. Restart the simulator. If the problem persists, report the issue to the technical team or FTD.aero Support. |

## Catch-all

| Code | Description | Expected | Action |
|---|---|---|---|
| `-1` | Unknown error. | N/A | Contact the technical team or FTD.aero Support. |

## Catalogue format

The catalogue is a flat JSON map, code to entry, so the panel looks a code up directly. Three fields are required.

| Field | Required | Purpose |
|---|---|---|
| `description` | yes | One sentence, operator language. Shown on the panel. |
| `solution` | yes | What the operator or technician should do next. |
| `expected` | yes | What a healthy system would have done, for comparison. |
| `sequence` | optional | `start`, `shutdown`, `restart` or `any` — which sequence can raise it. |
| `step` | optional | The step's own text, so the code can be matched to the configuration. |
| `severity` | optional | `fault` or `warning`, mirroring `abortOnError`. |

Every `codeOnError` in the sequence configuration has an entry; `-1` is the catch-all. Codes are strings, so negative and vendor ranges behave the same.

The catalogue delivered with this device is held beside this chunk as `assets/errors.json`.
