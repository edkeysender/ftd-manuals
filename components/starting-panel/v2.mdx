The station carries two mushroom-head emergency stop buttons above a portrait touchscreen. The touchscreen runs the starting panel software and is the only control used for normal start, restart and stop of the simulator. The emergency stops are hardwired and act independently of the software.

| # | Control | Function |
|---|---|---|
| 1 | **EMERGENCY STOP — TOTAL** | Wired to the EPO input of the UPS: cuts every electrical supply in the installation, including the simulator computers, control loading, the visual system and this panel — the touchscreen goes dark. |
| 2 | **EMERGENCY STOP — CLS** | Removes power from the control loading system only. The rest of the simulator stays powered. |
| 3 | **Touchscreen** | Status display and control surface: login keypad, start / restart / stop, session controls, brightness, volume and maintenance functions. |
| 4 | **Status bar** | Date and time in UTC on the left, temperature inside the IOS on the right. Visible on every screen. |

:::danger[Warning]
Never use an emergency stop to end a normal training session. Use **Stop** on the touchscreen. An emergency stop cuts power without an ordered shutdown and may require a technician to release the button and reset the affected systems before the simulator can be started again.
:::

## Screen layout

Every screen shares the same frame: status bar at the top, three main control buttons in the middle, current system state below them, session controls and the brightness slider at the bottom. The chevron at the top pulls the load and mode drawer down; the chevron at the bottom pulls the volume drawer up.

| Element | Function |
|---|---|
| Start (blue, left) | Runs the start sequence. Active only in **STOPPED**. |
| Restart (centre) | Shuts the simulator down and starts it again. Active only in **RUNNING**; press and hold. |
| Stop (red, right) | Ordered shutdown. Active only in **RUNNING**; press and hold for 3 s. |
| State text | Current system state, with step counter during transitions. Touching **RUNNING** opens the process list. |
| Flight in progress | Lights the FIP (flight in progress) sign on the wall of the simulator hall. Pressing it again switches the sign off. It has no effect on the simulator or on the session. |
| End Session & Logout | Logs the user out and returns the panel to the login keypad. The simulator keeps running. |
| Brightness slider | Dims the panel screen and the lighting inside the IOS together. Replaced by the volume slider while the volume drawer is open. |

## Login

When no session is open, a numeric keypad covers the control area and the buttons behind it are dimmed and inactive. The PIN is four digits and there is no confirm key: the panel logs in as soon as the fourth digit is entered. **C** clears the whole entry; the arrow key deletes the last digit.

:::caution
PINs are personal and must not be shared.
:::

## System states

The state text under the buttons is the primary indication of what the simulator is doing. Transitional states show a step counter and the name of the step in progress, for example `6/18 Wait after relay 2`.

| State | Meaning | Available controls |
|---|---|---|
| **STOPPED** | Simulator powered down and safe. Resting state between sessions. | Start |
| **STARTING** | Start sequence in progress, 18 steps. | None |
| **RUNNING** | All systems up. The simulator is available for training. | Restart, Stop |
| **STOPPING** | Ordered shutdown in progress, 15 steps, about 75 s. | None |
| **RESTARTING** | Shutdown and wake-up of the three computers, 14 steps, then straight back to RUNNING. | None |
| **ERROR** | A step failed. The panel shows the step index and the error code. | Stop, then start again |

## Starting the simulator

1. Confirm both emergency stops are released and the state text reads **STOPPED**.
2. Log in: enter the four-digit PIN.
3. Press the blue **Start** button. The state changes to **STARTING** and the counter begins at 1/18. The four power relays come up first, then the three computers are woken over the network.
4. Wait until the state reads **RUNNING**. Do not press any other control while the sequence runs.
5. Press **Flight in progress** when the training session begins.

Typical start time: about 66 s of fixed waits, plus however long the simulation and the control loading system take to report ready.

## Restarting

The restart and stop buttons are both guarded against accidental use: each is pressed and held for 3 s. While held, a progress bar fills above the buttons and the icon turns white. Releasing before the bar is full cancels the action.

On completion the simulator enters **RESTARTING**: the three computers are shut down, woken again over the network, and the panel waits for SIM ready and CLS service state — 14 steps, about 63 s. The power relays are not switched, so a restart is quicker than a stop and start.

:::note
A restart is used when a subsystem is unresponsive but the panel still reports RUNNING. If a restart does not clear the condition, the simulator is stopped and a maintenance request raised.
:::

## Stopping

1. Confirm the crew has left the flight deck and the session is finished.
2. Press and hold the red **Stop** button for 3 s. Releasing it early cancels the shutdown.
3. When the bar completes, the state changes to **STOPPING** with a 15-step counter, about 75 s. The computers are shut down first, then the power relays.
4. Wait for **STOPPED**.
5. Press **End Session & Logout**. The login keypad reappears; the device stays in **STOPPED**.

## After an emergency stop

The two stops behave differently, because **TOTAL** also removes power from the starting panel itself.

### CLS emergency stop

The panel stays powered and raises a red **CLS EMERGENCY STOP** banner under the state text, with a **RESET** button inside it. No start, restart or stop command is accepted while the banner is shown.

1. Confirm the reason for the stop has been dealt with and the area is clear, then release the mushroom head by turning and pulling it out.
2. Press **RESET** in the banner. The panel sends a CLS reset and clears the error state; the banner disappears and the control loading system returns to service.

:::caution
RESET stays inactive while the mushroom head is still pressed in. If the banner does not clear after a reset, the stop circuit has not returned to normal: report it as `E-201` and do not attempt a start.
:::

### TOTAL emergency stop

This button is wired to the EPO input of the UPS, so it cuts every electrical supply in the installation, including the UPS output and the starting panel itself. There is no battery hold-up: the screen goes dark immediately, and there is no banner and no RESET to press.

1. Confirm the reason for the stop has been dealt with and the area is clear, then release the mushroom head by turning and pulling it out.
2. Reset the UPS EPO and restore its output, in accordance with the UPS manufacturer's instructions.
3. Wait for the panel to power up and reach the login keypad.
4. Log in and start the simulator from **STOPPED**. Every system comes up from cold; the full start sequence is required.

:::caution
A TOTAL stop is an uncontrolled power cut for the host computers and for the UPS itself. Every use of it is reported so the state of the installation can be checked before the next session.
:::

## Load and mode drawer

The chevron at the top of the screen pulls the load and mode drawer down. It holds three selectors that decide which software load the simulator starts with. Selections take effect at the next start, and the active selector is outlined and labelled in green. With no selector active the simulator starts with the standard training load.

| Selector | Function |
|---|---|
| Development Mode | Starts the simulator with the development software load. Not to be used for training. |
| Maintenance Load | Starts with the maintenance load for servicing and troubleshooting. |
| QTG Mode | Starts in Qualification Test Guide mode, used for validation runs. |

:::caution
These functions are reserved for technical staff.
:::

## Volume drawer

The chevron at the bottom of the screen pulls the volume drawer up. The volume slider takes the place of the brightness slider on the same line, so only one of the two is shown at a time. The slider sets the level of panel acknowledgement tones and alarms. The setting is retained between sessions and does not affect flight deck audio.

## Process list

Touching the word **RUNNING** opens the process list. It shows every simulator computer by IP address with the software processes running on it, and allows individual processes, a whole computer or the entire installation to be started and stopped. **BACK** returns to the main screen.

| Element | Function |
|---|---|
| IP address row | One simulator computer. START and STOP on this row act on every process on that computer. |
| Process row | A single process, with its own START and STOP. |
| Status dot | Green: running. Grey: not running. Amber: starting, stopping or not responding — its buttons are dimmed until the process settles. |
| START ALL | Starts every process on every computer, in the normal order. |
| KILL ALL | Terminates every process immediately, without an ordered shutdown. Maintenance use only. |

:::caution
This screen is for technical staff. Stopping a process during a training session interrupts the session.
:::

Computer addresses and process names are site-specific. The current configuration is `70.84.68.10` instructor station, `.11` simulation host and visuals, `.12` flight deck displays and audio.

## Error codes

When a sequence step fails, the panel sets the state to **ERROR** and publishes the step index and the error code, so the state line reads for example `ERROR 10/18 — code 208`. Both numbers are recorded before retrying.

| Code | Sequence / step | Description | Action |
|---|---|---|---|
| `101` | shutdown, restart — Update sequence state | Sequence state could not be published at the start of a shutdown or restart. | Check the ARINC/support link to the panel. Retry the command. |
| `102` | shutdown, restart — Shutting down IOS | IOS computer (`70.84.68.10`) did not accept the shutdown command. | Check network connectivity and the remote shutdown credentials for the IOS PC. Shut it down manually if needed. |
| `103` | shutdown, restart — Shutting down Display | Display computer (`70.84.68.11`) did not accept the shutdown command. | Check network connectivity and the remote shutdown credentials for the Display PC. |
| `104` | shutdown, restart — Shutting down Avionics | Avionics computer (`70.84.68.12`) did not accept the shutdown command. | Check network connectivity and the remote shutdown credentials for the Avionics PC. |
| `105` | shutdown, restart — Wait for systems shutdown | Computers were still running when the shutdown wait expired. | Confirm all three PCs are off before power is removed. Report repeated occurrences. |
| `115` | shutdown — Wait for power shutdown | The 60 s wait after the relays were switched off did not complete. | Retry the shutdown. Report repeated occurrences. |
| `117` | shutdown — Wait for power shutdown | The 5 s wait between relay 4 off and power restore did not complete. | Retry the shutdown. Report repeated occurrences. |
| `119` | shutdown — Changing status state | Sequence state could not be set back to STOPPED after shutdown. | Check the ARINC/support link. Log out and back in to refresh the panel. |
| `200` | start — Update sequence state | Sequence state could not be published at the start of a start sequence. | Check the ARINC/support link to the panel. Retry the start. |
| `202` | start — Wait after relay 1 | The 1 s wait after relay 1 did not complete. | Retry the start. Report repeated occurrences. |
| `204` | start — Wait after relay 2 | The 1 s wait after relay 2 did not complete. | Retry the start. Report repeated occurrences. |
| `206` | start — Wait after relay 3 | The 1 s wait after relay 3 did not complete. | Retry the start. Report repeated occurrences. |
| `208` | start — Wait for power stabilization | The 60 s power stabilisation wait did not complete. | Retry the start. Report repeated occurrences. |
| `215` | start, restart — Wake-on-LAN Avionics | Wake-on-LAN packet to the Avionics PC was not sent or not acknowledged. | Check the broadcast address `70.84.68.255` port 9, the PC's WOL setting in BIOS and its network cable. |
| `216` | start, restart — Wake-on-LAN IOS | Wake-on-LAN packet to the IOS PC was not sent or not acknowledged. | Check the broadcast address `70.84.68.255` port 9, the PC's WOL setting in BIOS and its network cable. |
| `217` | start, restart — Wake-on-LAN Display | Wake-on-LAN packet to the Display PC was not sent or not acknowledged. | Check the broadcast address `70.84.68.255` port 9, the PC's WOL setting in BIOS and its network cable. |
| `218` | start, restart — Wait after wake-on-LAN | The 3 s wait after wake-on-LAN did not complete. | Retry the start. Report repeated occurrences. |
| `219` | start, restart — Wait for SIM ready | SIM did not report ready. | Open the process list and check the processes on `70.84.68.11`. Restart the simulator; if unchanged, raise a maintenance request. |
| `220` | start, restart — Wait for CLS service state | Control loading system did not reach service state 4. | Check the CLS emergency stop is released and reset, then restart. Report repeated occurrences. |
| `222` | start — Set sequence state to ready | Sequence state could not be set to RUNNING at the end of the start sequence. | Check the ARINC/support link. The simulator may be usable although the panel shows the wrong state; confirm before training. |
| `1001` | start — Projector wake-up | Projector did not respond to wake-up. | Check network connectivity and PJLink settings. |
| `-1` | any | Unknown error. | Check logs for details. |

Codes `101`–`105` and `215`–`220` are shared by the shutdown and restart sequences; the state text tells which one was running. The relay switching steps are commanded without feedback — the panel cannot tell whether a relay actually moved, so those steps report no error code and a relay failure surfaces later, as a computer that never wakes or a system that never reports ready.

## Fault reporting

When reporting a fault, record:

- Date and time in UTC as shown in the status bar.
- System state and step counter at the moment of the fault.
- Error code and the step index shown with it, and the full text on the state line.
- Which load selector, if any, was active.
- Whether an emergency stop was used, and which one.
- For a start or restart fault, whether the affected computer was reachable in the process list.
